# SNS集客bot 設計書（Whisky Data JP）

- 作成日: 2026-08-06
- 対象: X（メイン）＋ Instagram / Threads（サブ）
- 自動化範囲: **投稿の自動生成＋自動投稿**（リプライ・いいね・フォロー等のエンゲージメント自動化は対象外）
- 実装の下準備: `09-sns-bot/` 内にスケルトンコードあり（動作確認済み・dry-run対応）

---

## 1. 目的とゴール

サイト（whisky-data.jp）への流入を増やすため、毎日のSNS投稿を人手で書かずに自動生成・自動投稿する。

| 指標 | 1ヶ月 | 3ヶ月 | 6ヶ月 |
|------|-------|-------|-------|
| Xフォロワー | 300 | 1,500 | 5,000 |
| noteフォロワー | 100 | 500 | 2,000 |
| SNS経由の月間PV | — | 3,000 | 20,000 |

**前提**: 投稿は「サイトの記事・銘柄データ」が唯一のネタ源。botはサイトが生成済みのJSON/MDを読むだけで動く。

---

## 2. 対象SNSと役割分担

| SNS | 役割 | 投稿頻度 | 備考 |
|-----|------|---------|------|
| **X** | 主集客。記事告知＋データ豆知識＋質問で拡散 | 1〜2本/日 | ハッシュタグ必須。画像はサイトのOGPを再利用 |
| **Threads** | ビジュアル／カジュアル向けの再掲 | 1本/日 | Xと同文の転載でOK |
| **Instagram** | 将来。ビジュアル中心の二次利用 | 3本/週 | 本格運用はInstagram API申請後にPhase 3で追加 |

noteは**メイン記事チャネル**だがbotでの自動投稿はしない（noteの自動投稿APIは一般提供されておらず、手動投稿のまま）。botはnoteでなく**サイト記事URL**へ誘導する。

## 3. 全体アーキテクチャ

```
                        ┌─────────────────────────────────────┐
  サイト(静的)           │  09-sns-bot/  (Node.js ESM, 依存なし)   │
 ┌──────────────────┐   │                                     │   ┌──────────┐
 │ src/content │──▶│ 1. content/load  記事・銘柄JSONを読む  │   │ X API    │◀──── 投稿
 │  /blog/*.md      │   │ 2. content/pick  今日のネタを選ぶ      │──▶│ (Bearer) │
 │  /whiskies/*.json│   │ 3. generate/copy 投稿文を組み立てる    │   └──────────┘
 │  /distilleries/* │   │    └─ generate/llm (任意・有料)        │──▶ Threads API
 │ public/ogp/ │   │ 4. post/         各SNSに投稿          │   (Graph API)
 │  whisky-*.png    │   │ 5. store/history 履歴で重複・上限管理   │   └──────────┘
 └──────────────────┘   └──────────────────────────────────────┘
                                    ▲
                   毎朝のスケジュール実行（opencode schedule / Windows タスク）
```

**実行単位**: `node 09-sns-bot/src/index.mjs post` を1回 = 1日分の1SNS投稿。実行されるたびに
「履歴を見て重複せず、本日分の上限内で、最も優先度の高いネタ」を1本選んで投稿する（冪等・安全）。

## 4. コンテンツパイプライン

### 4-1. ネタ源（入力）

| ソース | 場所 | 使うフィールド |
|--------|------|---------------|
| 記事 | `src/content/blog/*.md` | title / date / excerpt / tags / category / compare |
| 銘柄 | `src/content/whiskies/*.json` | name / rating / priceYen / flavor / notes / type |
| 蒸留所 | `src/content/distilleries/*.json` | name / region / history（概要） |
| 画像 | `public/ogp/whisky-*.png` | 投稿に添付するアイキャッチ |

※記事は `draft: true` と未来日付を除外。`compare` 付き記事は「比較系」、それ以外は「告知系」に分類。

### 4-2. 選定ロジック（pick）

1. 履歴にまだ投稿していない記事（未告知の新しい記事を最優先）
2. 全銘柄のうち rating が高く、まだ紹介していない銘柄
3. 上記がない場合 = 質問系（エンゲージメント狙い）を生成

選定ルールは `09-sns-bot/src/content/pick.mjs` の `PRIORITY` で変更できる。

### 4-3. 画像

記事 → 対応するOGP画像（`ogp/whisky-<slug>.png`）があれば添付。
銘柄 → `ogp/whisky-<id>.png`。なければ画像なし投稿（XはテキストのみでもOK）。

## 5. 投稿パターン（copy.mjs）

`03-templates/x-post.md` のパターンを踏襲しつつ、サイトデータから埋め込む。

| パターン | 内容 | 生成 |
|---------|------|------|
| **A. 記事告知** | キャッチ＋補足＋記事URL | 記事の title/excerpt から |
| **B. データ豆知識** | 銘柄の評価・価格・フレーバー | 銘柄JSONから |
| **C. 質問投げかけ** | 2択/1択＋ハッシュタグ | テンプレ＋銘柄データから |
| **D. 蒸留所紹介** | 蒸留所の名前＋1行紹介＋記事/銘柄 | 蒸留所JSONから |

**ハッシュタグ**: `#ウイスキー #Whisky` を基本に、カテゴリ別タグを追加
（`#ジャパニーズウイスキー` / `#スコッチ` / `#ウイスキー好きと繋がりたい` 等）。

### 出力例（パターンA）

```
山崎12年 vs 白州12年、データで決着させました。
Whiskybase口コミ312件をレーダーチャートで可視化👇
https://whisky-data.jp/2026-08-06-yamazaki-vs-hakushu/
#ウイスキー #Whisky #ジャパニーズウイスキー
```

## 6. 投稿文の生成方式（2段階）

### Phase 1: テンプレート生成（**無料・デフォルト**・今回実装済み）
ルールベース。記事フロントマターと銘柄JSONを直接テンプレに流し込む。
- メリット: APIコスト0・決定的（同じ入力→同じ出力）・内容の品質が保証される
- デメリット: 文が単調になる

### Phase 2: LLM生成（**有料・任意**・`generate/llm.mjs` にスタブ実装済み）
OpenAI互換API（Claude / GPT など）にデータを渡してバリエーション豊かな文を生成。
- `LLM_API_KEY` / `LLM_BASE_URL` / `LLM_MODEL` が未設定なら自動的にテンプレート生成へフォールバック
- 1件あたり概算0.1〜0.5円程度（モデルによる）。予算ゼロ方針ならPhase 1のままで問題ない
- 出力は**必ず人間レビュー用に `--dry-run` で確認**してから本番化

## 7. スケジューリング

実行は2択。まず **opencodeのscheduleスキル**で毎朝1回だけ走らせるのがおすすめ。

| 方式 | 内容 | 対象 |
|------|------|------|
| opencode schedule | スキルで「毎朝9時: `node 09-sns-bot/src/index.mjs post --channel all`」を定期タスク登録 | 開発PCを普段つけている場合 |
| Windows タスクスケジューラ | 同じコマンドをbat経由で毎日実行 | 常時起動のPC / サーバー |

**時間帯（`03-templates/x-post.md` より）**:

| 時間帯 | 投稿タイプ |
|--------|-----------|
| 7:00〜8:00 | データ豆知識（通勤時間） |
| 12:00〜13:00 | 質問投げかけ（ランチ） |
| 20:00〜22:00 | 記事告知（飲酒タイム） |

1日の投稿回数は `BOT_DAILY_LIMIT`（既定2）で制限。夜間・早朝は避ける（Xは深夜連投をスパムと誤判定しやすい）。

## 8. API設定とコスト

### X（メイン）
- X API v2。Freeプランでも**書き込み（投稿）は月500回**まで可能（要：Twitter DeveloperアプリでWrite権限を申請）
- 認証: Bearerトークン（OAuth2.0）で `/2/tweets` にPOST
- **要検証**: 新規DeveloperアカウントのFree枠でWriteが付与されるかは現状のX方針で変わる。付与されない場合の代替は Buffer API / セルフホストの Postiz / n8n
- 投稿時のURLはそのままテキストに入れるとカード展開される（サイトのOGP設定済み）

### Threads / Instagram
- Threads API: Facebookアプリ＋Threadsビジネス/クリエイターアカウント＋Instagramアカウント連携が必要。`/me/threads` に投稿
- Instagram: ビジネスアカウント＋Graph API（パブリッシャー権限）が別途必要
- どちらも**アプリレビュー/API利用申請**が通るまで使えないため、Phase 3（運用安定後）で追加

### LLM（任意）
- OpenAI互換API（Anthropic / OpenAI / DeepSeek等）。`LLM_BASE_URL` で差し替え可能

**予算ゼロの現実解**: Xのみ・テンプレート生成・手動確認つき で開始。APIが通る前は `--dry-run` で本文を出して手動ツイートする。

## 9. 安全策・フェイルセーフ

| 対策 | 実装 |
|------|------|
| **dry-run（デフォルトON）** | `BOT_DRY_RUN=true` の間は一切投稿せず、生成文と投稿先を標準出力に出す |
| 重複防止 | `store/history.json` に投稿済みネタIDを記録し、同じネタを再投稿しない（date-basedで重複も排除） |
| 1日あたり上限 | `BOT_DAILY_LIMIT` 超過分は投稿しない |
| レート制限 | X/Threadsは投稿APIの規約上、連続投稿禁止。**1実行=1投稿**に固定し、実行間隔はスケジューラ側で空ける |
| アカウント保護 | 手動投稿の実績（1日1〜2本、数週間）を積んでから自動化に切り替える |
| 手動レビュー | 本番投稿前は必ず `post --dry-run` → 確認 → `post` の流れを守る |
| 認証情報 | `.env` は `.gitignore` に入れる（リポジトリにコミットしない） |

## 10. コンプライアンス（重要）

1. **Amazonアソシエイト**: 規約により**SNS（X/Instagram等）へのアフィリエイトリンク掲載は禁止**。
   botの投稿にはアフィリエイトURLを**一切含めない**。リンク先はサイト記事（サイト内でアフィリンクを出す）かnoteにする。
2. **開示**: 自社アカウントの告知投稿は厳密には広告扱いではないが、関係性がある場合は `#PR` 等の開示を推奨。
3. **X規約**: スパム行為（無関係なハッシュタグ乱用、過剰なハッシュタグ、連投、類似文の機械的連投）はBAN対象。
   - ハッシュタグは投稿あたり**3〜4個まで**
   - 生成文はテンプレ＋ランダムな文体差で**完全同一文を連投しない**
4. **Threads/Instagram規約**: 自動投稿は公式API経由のみ。サードパーティの非公式クライアント禁止。
5. **著作権**: 画像はサイト既存のOGP（自前生成・CCライセンス）のみ使用。外部画像のスクレイプ投稿はしない。
6. **虚偽表示**: 評価・価格は「Whiskybaseデータ」「編集部推定」と出典を明記（サイトのデータ原則と同じ）。

## 11. 計測とKPI

投稿ごとに記録・確認する項目（手動 or 後日スプレッドシート集計）:

| 項目 | 確認方法 |
|------|---------|
| インプレッション・いいね・リポスト・リプライ | Xアナリティクス |
| プロフィール訪問 → サイト流入 | サイトのGA4（設置済みなら） |
| フォロワー増加数 | Xアナリティクス / 週次 |
| パターン別の反応 | パターンA/B/C/Dごとに集計して改善 |

**フィードバックループ**: 2週間ごとに反応の良いパターンを確認し、`copy.mjs` のテンプレと
`pick.mjs` の優先度を調整する。エンゲージメントの悪いパターンは間引く。

## 13. 技術構成と下準備（今回作成したもの）

- **ランタイム**: Node.js 20+（`fetch` 組み込み、外部依存ゼロ。`.env` 読み込み込み）
- **コード**: `09-sns-bot/src/`（ESM・JSDoc付き）
  - `index.mjs` — CLIエントリ（`post` / `draft` / `history` / `test`）
  - `config.mjs` — `.env` 読み込み・検証
  - `content/load.mjs` — 記事・銘柄・蒸留所を読む
  - `content/pick.mjs` — 今日のネタ選定（重複除外・優先度）
  - `generate/copy.mjs` — パターンA〜Dの投稿文生成（無料・テンプレ）
  - `generate/llm.mjs` — LLM生成（任意・有料、未設定ならフォールバック）
  - `post/x.mjs` / `post/threads.mjs` — APIクライアント（未認証は明示的にスキップ）
  - `store/history.mjs` — 投稿履歴（JSON）・上限管理
- **データ**: `09-sns-bot/data/history.json`（自動生成・gitignore対象）
